# Writing rules for this repo

These apply to ALL text Claude writes into this repo: code comments, UI
copy, README/docs, commit messages, JSON/TS data, anything user-facing or
otherwise.

## No AI markers

- **No em dashes (—) or en dashes (–) anywhere.** Use a comma, period,
  colon, or parentheses instead. For numeric ranges use a plain ASCII
  hyphen (e.g. "Quran 43:13-14").
- **No AI-prose voice.** Avoid hedging transitions like "delve into",
  "tapestry", "in the realm of", "it's worth noting that", "moreover",
  "furthermore", "navigate the landscape", "unlock the power of",
  "leverage", "elevate", "embark on a journey".
- **No filler.** Don't open with "I'll", "Let's", "In this guide we
  will" or end with "Hope this helps!" Just write the thing.
- **No marketing hype** in UI copy: no "seamlessly", "effortlessly",
  "powerful", "intuitive", "robust", "cutting-edge".
- **Short, direct sentences.** If a sentence reads like a press release,
  rewrite it.

## When in doubt

Imagine a thoughtful human writer with no LLM in the loop. Would they
write it that way? If not, rewrite.
